# ドキュメント管理ルール

## はじめに

本プロジェクトでは、ドキュメントを Docusaurus（Markdown）× Git リポジトリで管理する。

### Docusaurus（Markdown）× Git リポジトリで管理する理由

- **AI 活用との親和性**：Markdown はプレーンテキストであるため、GitHub Copilot 等の AI ツールがドキュメントを直接読み書きできる。ドキュメント生成・レビュー・検索への AI 活用が容易になる。
- **バージョン管理・並行開発への対応**：ソースコードと同様にブランチ管理できる。バージョンごとのブランチを切ることで、複数バージョンの並行メンテナンスが可能になる。
- **レビュープロセスの標準化**：PR（プルリクエスト）ベースのレビューフローをドキュメント更新にも適用できる。変更差分が明確になり、レビュー品質・承認フローを統一しやすい。
- **変更履歴の追跡**：誰が・いつ・何を変更したかをコミット履歴で追跡できる。
- **開発フローとの統一**：開発者が日常的に使うツール（GitHub）でドキュメントも管理するため、別途ツールの習熟コストが不要になる。
- **自動デプロイによる即時公開**：GitHub Actions と連携することで、マージ・PR 作成をトリガーに自動でサイトが更新される。

### Notion との使い分け

すべてのドキュメントを Docusaurus で管理すると、継続的なメンテナンスが不要なフロー型情報とストック型情報が混在し、管理が煩雑になるため、ドキュメントの性質によって管理ツールを使い分ける。  
**閲覧の権限管理が必要な情報は、Docusaurusに記載できないため、閲覧者が限られる情報だけConfluenceに記載してNotionのリンクを記載する。（例えばシークレット情報はkeyのみを記載し、valueは必要な人に権限を絞ってNotionに記載する）**

| 種別                                                           | 管理ツール                 | 例                                                   |
| -------------------------------------------------------------- | -------------------------- | ---------------------------------------------------- |
| **フロー型**（一時的・都度更新・ストックしても効果が薄いもの） | Notion                 | 議事録、スプリントレビュー記録、調査メモ、議論の経緯 |
| **ストック型**（継続参照・長期メンテナンスが必要なもの）       | Docusaurus（本リポジトリ） | 設計書、要件定義書、ガイドライン、手順書             |

## 更新ルール

- 更新者に記載されたメンバーがメンテナンスする
  - 更新者以外が更新しても良いが、更新者のレビューは必須とする（例えばPOAが設計書を更新しても良いが、DEVのレビューは必須）
  - ドキュメントの更新は **DoD（Definition of Done）** の一部として定義し、作業完了の条件に含める（POAがPBI起票する際に要件定義資料を更新することも同様に必須）

## ローカルプレビュー手順

### 前提

- Node.js >= 20

### ローカルサーバー起動手順

1. リポジトリをクローン

   ```bash
   git clone https://github.com/（未記入）
   cd （未記入）
   ```

2. 依存パッケージをインストール

   ```bash
   npm install
   ```

3. ローカルサーバーを起動

   ```bash
   npm start
   ```

4. ブラウザで `http://localhost:3000` にアクセスしてプレビューを確認

5. `docs/` 配下の Markdown ファイルを編集するとホットリロードで即時反映される

### VSCode 設定手順

1. 拡張機能 [Markdown All in One](https://marketplace.visualstudio.com/items?itemName=yzhang.markdown-all-in-one) をインストール

2. `settings.json` に以下を追加する（保存時に自動フォーマットが有効になる）

   ```json
   "[markdown]": {
       "editor.defaultFormatter": "yzhang.markdown-all-in-one",
       "editor.formatOnSave": true
   }
   ```

## デプロイ

- GitHubActionsにより自動デプロイされる（手動操作は不要）
